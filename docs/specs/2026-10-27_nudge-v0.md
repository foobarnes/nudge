# Nudge v0 Specification

## Executive Summary

- **Problem:** When someone asks you to review their code on GitHub, the request is easy to miss. It sits in a busy inbox. Nobody can see how long the other person has been waiting. Slow reviews block teammates.
- **Solution:** A tiny Mac app lives in the top bar. It taps you on the shoulder when a review request arrives. Then it shows a running clock of how long that person has been waiting on you, until you send your review.
- **Why now:** Nothing outside forces the timing. It is a new personal tool. Waiting only means more missed review requests.
- **Decisions worth knowing** (chose → over):
  - The app asks GitHub every minute, all on your Mac → over instant alerts that need a server on the internet
  - It borrows your existing GitHub command-line login → over its own sign-in screen
  - The clock runs only while a request to you is open, restarts on a new request, and skips drafts → over counting from when the change was opened
  - Clock colors use work hours, but the clock shows real time → over pure work-hour counting or pure real time
  - People build it from source for now → over a signed download (tracked in [issue #1](https://github.com/foobarnes/nudge/issues/1))
- **Deferred:** signed downloads and Homebrew install ([#1](https://github.com/foobarnes/nudge/issues/1)), auto-update, GitHub Enterprise servers, keyboard shortcuts, per-team rules, a cute mascot.
- **Risk: LOW** — a new standalone app that only reads from GitHub. Nothing is shared or changed on GitHub. The one risky spot is custom review commands. They use text that other people write, so that text is kept apart from the command itself.
- **Est. tokens:** ~1.1M
- **Est. LOC:** ~+3,000/−0
- **Ambiguities / inconsistencies:** If GitHub's history for a change is too long, the app may not find when the request started. The spec shows no clock in that case; that could surprise people. How two terminal apps run commands still needs a quick test on a real machine (planned as an early check).
- **Needs your eyes?** **Yes** — custom review commands run on your computer using text that strangers can write (change titles). The safety design for that (Action Templates) is worth a look.

## Requirements

### Functional Requirements

- **Detect active review requests**
  - Every 60s (and on wake from sleep), fetch open, non-archived PRs where a review is requested from the viewer or one of the viewer's teams.
  - A PR is *waiting* only while a request to the viewer (user or team) is currently active and the PR is not a draft. A bot's draft (an automated fix that requested review) still counts. Submitting a review removes the request on GitHub, so it stops the timer.
  - **Request start** = latest `ReviewRequestedEvent` targeting the matched reviewer; if a later `ReadyForReviewEvent` exists, use that instead.
  - Direct and team requests are both tracked; direct wins when both exist.
- **Show waiting PRs**
  - Menu bar item: template glyph + count (no number at zero), updated once per minute.
  - Dropdown panel from the status item: rows with live timers, sync status, display-mode switch, Settings…, Quit.
  - Floating pill (glass capsule): collapsed shows `count · oldest timer`; on hover it morphs open into the full row list.
  - Display modes: **Menu bar only**, **Widget always**, **Auto** (default: pill appears when ≥1 PR is waiting, leaves at zero).
- **Timers and escalation**
  - Display wall-clock elapsed time: compact `4h 12m` / `2d 3h` at rest; live `4:12:07` while the pill is expanded or the dropdown is open.
  - Tiers by *working hours* (default Mon–Fri 09:00–18:00 local; editable): Fresh < 4 wh, Amber ≥ 4 wh, Red ≥ 8 wh (thresholds editable).
  - On each tier crossing: the row's dot wiggles once and the pill returns to full opacity for 3s. On reaching Red: one reminder notification per request.
- **Notify and act**
  - New request → native notification (`<requester> requested your review · <repo>#<n> <title>`) with **Open** and **Snooze 1h** actions; the pill bounces and the new row draws in.
  - Row click opens the PR in the default browser. Row actions: **Start review** (runs actions), **Snooze** (1h / until next working-day start), **Hide until re-requested**.
  - Per org and per repo notification rule: **Notify** / **Silent** (shown, no banner) / **Hidden** (ignored). Repo rule overrides org rule; default Notify.
  - Start-review actions are user-defined in Settings (see Action Templates).
- **App lifecycle**
  - Agent app (no Dock icon). Launch-at-login toggle (default off). Settings window with tabs: General, Notifications, Actions, About.

### Non-Functional Requirements

- **Lightweight**
  - No third-party Swift dependencies. Idle memory < 60 MB; ~0% CPU between syncs.
  - 1s redraws only while a live-seconds surface is visible; otherwise minute-aligned ticks with timer tolerance.
- **API budget**
  - One GraphQL query per minute (≈60 of 5,000 points/hr) plus one team-membership query per hour.
- **Design**
  - macOS 26+ Liquid Glass; SF Pro Rounded digits; motion only on state change; every animation gated by Reduce Motion (falls back to crossfade/no-op).
- **Privacy**
  - Token never written to disk by Nudge; no telemetry. Nudge's own network traffic goes only to `api.github.com`. Browser opens and user-defined actions may contact other services. Those are the user's commands, not Nudge's traffic.
- **Repo hygiene (public repo)**
  - No personal or employer names, org names, or real PR data in code, fixtures, screenshots, or docs. Fixtures and screenshots are fully synthetic (`acme/*`, `octocat`, made-up titles, numbers, and timestamps).
  - Accepted exception: the repo owner's public GitHub handle appears where ownership requires it (repo/issue URLs, bundle ID `io.github.foobarnes.nudge`). Commits use the GitHub no-reply address.

## Technical Design

### Architecture

```text
┌──────────── Nudge.app (AppKit shell, SwiftUI views) ─────────────┐
│ StatusItemController ── DropdownPanel (NSPanel, anchored)        │
│ PillPanel (NSPanel: nonactivating, floating, all Spaces)         │
│ Settings scene (SwiftUI)  ·  NotificationCenter delegate         │
│                │ observes                                         │
│        AppModel (@Observable, @MainActor)                         │
└────────────────┼──────────────────────────────────────────────────┘
                 │
┌────────────── NudgeKit / NudgeCore (pure Swift, unit-tested) ────┐
│ TokenProvider (`gh auth token`) → GitHubClient (GraphQL)          │
│ SyncEngine: poll → ReviewRequestResolver → [WaitingPR]            │
│ RuleResolver · WorkingHours/Tier · ActionTemplate · Store         │
└───────────────────────────────────────────────────────────────────┘
```

- **Shell:** AppKit `NSStatusItem` + two `NSPanel`s hosting SwiftUI (`NSHostingView`). `MenuBarExtra` is not used: it cannot be opened or closed from code, and the floating pill needs `NSPanel` collection behaviors anyway.
- **Sync loop:** `SyncEngine` actor runs on a 60s timer (tolerance 10s), immediately on launch, on `NSWorkspace.didWakeNotification`, and on a manual "Sync now" action. Backoff on failure: 60s → 2m → 5m (cap), reset on success. On HTTP 403/429 with `retry-after` or `x-ratelimit-reset`, wait until then.
- **Auth:** `TokenProvider` resolves `gh` from `/opt/homebrew/bin/gh`, `/usr/local/bin/gh`, then `/bin/zsh -lc 'command -v gh'` (Finder-launched apps lack the shell PATH). It runs `gh auth token --hostname github.com` and keeps the token in memory only. On 401 it re-reads once, then surfaces an auth error.
- **Teams:** hourly query of the viewer's team memberships across orgs (needs `read:org`; the `gh` default scopes include it).
- **Notifications:** `UNUserNotificationCenter`, category `REVIEW_REQUEST` with actions `OPEN` and `SNOOZE_1H`; standard interruption level. Notification identifier = request key, so a repeat post replaces rather than duplicates.
- **First launch:** the first complete sync silently seeds `seenRequestKeys`, and seeds `redNudgedKeys` only for requests already Red; only requests that appear afterwards notify. This avoids a burst of banners for an existing backlog.
- **Single-flight sync:** launch, wake, manual, and timer triggers coalesce into one in-flight sync. A trigger during a sync schedules exactly one follow-up. Results carry a monotonically increasing generation, and older generations are discarded. Request timeout is 20s. "Sync now" respects a 10s cooldown and any rate-limit wait.
- **Rate limits and errors:**
  - GraphQL can report rate limiting with HTTP 200, so Nudge inspects `errors[].type` (`RATE_LIMITED`) as well as 403/429 and the `x-ratelimit-remaining`/`x-ratelimit-reset`/`retry-after` headers.
  - `INSUFFICIENT_SCOPES` → "Run `gh auth refresh -s read:org`"; HTTP 401 → re-read token once, then the auth error.
  - Actual cost is read from `rateLimit { cost }` and logged. Measured in Phase 0: 1 point per search page (≤ 4 per sync, ≤ 240/h at 60s), so v0 has no adaptive interval. Rate-limit responses still use the backoff above.
- **Pagination:**
  - The search connection pages 50 at a time (max 4 pages). Search includes drafts, so the cap is "200 search results", shown as "200+ results — some may be missing" and the snapshot is marked incomplete.
  - `reviewRequests(first: 100)` (the API max). If `hasNextPage` is true, the PR is refetched by node ID and **all** reviewer pages are read before resolving, so precedence and `otherTeams` see the full set.
  - Teams: `viewer { organizations(first: 100) { nodes { login teams(first: 100, userLogins: [$login]) { nodes { slug } pageInfo { hasNextPage endCursor } } } pageInfo {…} } }`, fully paginated, hourly.
- **Resolution with several matching targets:** direct beats team. Among teams, the one with the latest matching `ReviewRequestedEvent` wins; the others go to `otherTeams` and appear in hover detail. Requests whose reviewer is null or not a User/Team (Bot, Mannequin, EnterpriseTeam) are skipped per request. A null *actor* does not skip anything; it only changes the wording. One bad node never fails the snapshot.
- **Notification wording** uses the event actor, not the PR author: `<actor> requested your review`. Fallbacks: `Review requested` when the actor is null; `<actor> requested <team>'s review` for team requests.

### Data Model

```swift
struct WaitingPR: Identifiable, Hashable {
    let id: String              // PR node ID
    let repo: String            // "acme/api"
    let number: Int
    let title: String
    let url: URL
    let author: String
    let headRef: String
    let via: RequestTarget      // .direct or .team(org:slug:)
    let otherTeams: [RequestTarget] // additional matching team requests (hover detail)
    let requestedBy: String?    // actor of the ReviewRequestedEvent; nil if unknown/ghost
    let requestKey: String      // stable identity, see below
    let requestedAt: Date?      // matched ReviewRequestedEvent.createdAt (nil if unknown); used for episode detection
    let waitingSince: Date?     // timer start; nil = "request time unknown"
}

struct SyncSnapshot {
    let prs: [WaitingPR]
    let isComplete: Bool        // false if any page, org (SSO), or node failed
    let fetchedAt: Date
}

enum RequestTarget: Hashable { case direct, team(org: String, slug: String) }
enum Tier { case fresh, amber, red }
enum NotifyLevel: String, Codable { case notify, silent, hidden }
enum DisplayMode: String, Codable { case menuBarOnly, widgetAlways, auto }

struct ReviewAction: Codable, Identifiable {
    var id: UUID
    var name: String            // "Check out locally"
    var symbol: String          // SF Symbol name
    var kind: Kind              // .terminal, .background, .openURL
    var template: String        // "gh pr checkout {number} --repo {repo}"
    var repeatCount: Int        // 1...5
    var runOnStart: Bool        // included when the Start button is pressed
    enum Kind: String, Codable { case terminal, background, openURL }
}
```

**Persisted (UserDefaults, Codable JSON per key):**

- `displayMode`, `launchAtLogin` (mirrors `SMAppService` status), `workingHours` (weekday set, start, end), `tierThresholds` (amber/red working hours), `terminalApp` (`ghostty` | `terminal`).
- `orgRules: [String: NotifyLevel]`, `repoRules: [String: NotifyLevel]`.
- `actions: [ReviewAction]`.
- `seenRequestKeys: Set<String>`, `redNudgedKeys: Set<String>`, `snoozes: [requestKey: Date]`, `hiddenRequestKeys: Set<String>`. Keys are pruned only after a **complete** snapshot no longer contains them for 24h. An incomplete snapshot (SSO gap, failed page, cap reached) never prunes, so a PR that drops out temporarily doesn't come back as "new".
- `pillPositions: [displayUUID: Anchor]`, where `Anchor` = edge + offset fraction.
- All of the above is namespaced by GitHub login (`state.<login>.*`). An account switch in `gh` loads that login's state and clears the team cache.

**Request identity (`requestKey`):**

- Normally the GraphQL node `id` of the matched `ReviewRequestedEvent`, which is stable per request.
- When no matching event is found (history unavailable), it is `<prID>#<target>#unknown`.
- A ready-for-review transition changes `waitingSince` but **not** the key.
- A genuine re-request creates a new event, and therefore a new key.

**Notify only on a new waiting episode:** a banner fires when a `requestKey` is unseen **and** either the PR was not waiting in the previous complete snapshot, or the matched event's `createdAt` is later than that snapshot's `fetchedAt`. The second condition catches a "review submitted, then re-requested" that happens between two polls.

- **Same-episode key changes:** the key changes but the event isn't newer than the last complete snapshot, e.g., the direct request is removed while an older team request remains, or the time goes from unknown to known. Nudge silently **migrates** all per-key state (seen, red-reminded, snooze, hidden) from the old key to the new one.
- **Draft → ready:** if the key is unseen (requested while draft), this notifies once, because that's when it starts waiting on you.

**Behavior matrix** (one row per state; "count" = menu bar number and pill count):

**Precedence** (first match wins): Hidden rule → Hidden until re-requested → Silent rule → Snoozed → Notify. Silent suppresses every banner and reminder, whether or not the request is snoozed. A snooze defers the red reminder only under Notify. The "Time unknown" row is a modifier: it removes the timer and reminders, and banners still follow the precedence above.

| State | Row visible | In count | Timer | Tier motion | New-request banner | Red reminder |
| --- | --- | --- | --- | --- | --- | --- |
| Notify rule | yes | yes | runs | yes | yes | yes |
| Silent rule | yes | yes | runs | yes | no | no |
| Hidden rule | no | no | n/a | no | no | no |
| Snoozed | in a collapsed "Snoozed (n)" group | no | runs | no | no | deferred: fires at expiry if red |
| Hidden until re-requested | no | no | n/a | no | no | no |
| Time unknown | yes, timer `—` | yes | none | no | yes (once) | no |

Snooze expiry returns the row with a bounce and no banner, except a still-pending red reminder. Changing a rule takes effect on the next render. Hidden → Notify never back-fills banners for already-seen keys.

### UI/UX

**Visual language:** Liquid Glass capsules inside a `GlassEffectContainer`; SF Pro Rounded, monospaced digits; template-tinted dots.

- **Direct request:** filled dot `●`, primary text.
- **Team request:** hollow ring `◎`, secondary text. Hover reveals a `via acme/backend` caption line.
- **Tier color:** applies to the dot and the timer text. Fresh uses the neutral secondary color, Amber is system orange, Red is system red. All three are static: motion happens only at the tier-crossing wiggle, never as a continuous loop.
- **Size limits:** the expanded pill and the dropdown are at most 360×440pt and scroll beyond that. Titles truncate at the tail with a full-title tooltip. The panel is clamped on-screen.
- **Keyboard & VoiceOver:**
  - The dropdown becomes key while open: ↑/↓ move between rows, Return opens a row, ⌘↩ runs Start, Esc closes.

It becomes key only after a click inside it, so Esc (`cancelOperation`) can collapse it, and it resigns key on collapse. The pill stays expanded while a child menu is open (`NSMenu.didBegin/EndTrackingNotification`).
  - Every row has an accessibility label, e.g. "acme/api 4211, Fix token refresh, waiting 4 hours 12 minutes, team backend". Every action is reachable without hover via the VoiceOver actions rotor.

**Dropdown (click status item):** same row view as the expanded pill, in a glass panel anchored below the status item. Footer: segmented display-mode control (Menu bar · Widget · Auto), `Sync now`, `Settings…`, `Quit`. Closes on outside click or Esc.

**Status item:** template glyph (custom "clock-in-bubble" SF Symbol-style glyph, fallback `clock.badge`) plus count. At zero, glyph only. On error the glyph swaps to a variant with a small `!` badge.

**Settings (SwiftUI `Settings` scene, tabs):**

- **General:**
  - Display mode.
  - Launch at login.
  - Working hours (weekday toggles, start/end pickers).
  - Tier thresholds (amber / red working hours).
  - Terminal app.
- **Notifications:**
  - Org list (auto-populated from viewer orgs + orgs seen in results, plus the viewer's own login for personal repos), each with a Notify/Silent/Hidden picker.
  - "+ Add repo override" (`owner/name` text field with validation) listing overrides under their org.
- **Actions:**
  - Reorderable list.
  - Editor fields: name, symbol picker (text field + preview), kind, template (monospaced, with token chips `{url}` `{repo}` `{owner}` `{name}` `{number}` `{branch}` `{title}`), repeat count, run-on-Start toggle.
  - Live preview of the rendered command for a sample PR.
- **About:** version, link to the repo, `gh` path + login status.

**Activation:** to show Settings from an agent app, temporarily set the activation policy to `.regular`, activate, open Settings, and return to `.accessory` when the window closes. A Dock icon showing *only while Settings is open* is accepted. This is the one exception to "no Dock icon".

**Settings validation:**
- Working-day start must be before end; overnight ranges aren't supported in v0.
- Thresholds must satisfy `0 < amber < red`.
- With zero working days, "Snooze until next working day" is disabled and tiers never escalate.
- Working time uses the *current* system time zone for all history and recomputes on a time zone change. Day windows are built with `Calendar.date(bySettingHour:minute:second:of:matchingPolicy: .nextTime, repeatedTimePolicy: .first)`: a start or end in a skipped hour moves to the next valid time, and a repeated hour uses its first occurrence. Elapsed time inside a window is real seconds, so the window is 1h shorter on spring-forward and 1h longer on fall-back. "Next working-day start" uses the same rule.
- If sleep or a settings change jumps a request past both thresholds, the tier goes straight to Red with one wiggle and at most one reminder.
- While the snapshot is stale, no reminders fire. Deferred reminders fire on the next good sync.

### Action Templates

- **Tokens:** `{url} {repo} {owner} {name} {number} {branch} {title}`.
- **Shell kinds never put PR data into shell source.** Values like the PR title come from whoever opened the PR, so they are untrusted.
  - **Token expansion:** each token renders as a parameter reference: `{title}` → `${NUDGE_PR_TITLE}` (also `NUDGE_PR_URL`, `_REPO`, `_OWNER`, `_NAME`, `_NUMBER`, `_BRANCH`).
  - **Passing values:** Nudge writes a per-run script to a private `0700` temp directory. The script starts with `emulate -R zsh` (resets options a user's `.zprofile` may have changed, such as `sh_word_split` and `glob_subst`), then holds `export NUDGE_PR_…='<value>'` lines, each value single-quote escaped (an assignment context, so this is safe), followed by the user's rendered template. Nudge runs it with `/bin/zsh -l <script>`.
  - **Why it's safe:** zsh doesn't re-parse expansion results for command substitution, and by default it doesn't word-split or glob them. Tokens therefore work bare, inside double quotes, or inside `$(…)`.
  - **Single quotes:** the editor **rejects** templates with a token inside single quotes, because it would never expand there.
  - **Cleanup:** the script deletes itself on exit (`trap 'rm -f "$0"' EXIT`).
- **`openURL` kind:** encoding depends on the URL component.
  - The scheme and host must be literal template text (a token before the first `/` after `://`, or in the scheme, is a validation error).
  - Tokens in path segments are percent-encoded with `urlPathAllowed` minus `/`. Tokens in query values are percent-encoded with `urlQueryAllowed` minus `&=+#?`.
  - Schemes are limited to `https` plus the custom schemes the user explicitly allows in the Actions tab; `file`, `javascript` and `data` are always rejected.
- **Execution contract:**
  - **Working directory and order:** working dir `~`. Start launches the `runOnStart` actions in list order without waiting for any to finish; a failing launch doesn't stop the rest.
  - **Repeats and double-clicks:** `repeatCount` applies to every kind (N windows, N processes, or N URL opens). Start is debounced per PR for 2s.
  - **Kinds:**
    - `terminal`: Ghostty → `open -na Ghostty.app --args --wait-after-command=true -e /bin/zsh -l <script>` (without the flag the window closes when the command exits; verified on Ghostty 1.3.1); Terminal.app → AppleScript `do script` with the script path passed through `quoted form of`. Needs `NSAppleEventsUsageDescription`. If Automation permission is denied, a notification links to System Settings › Privacy › Automation.
    - `background`: `Process` with the same script, at most 4 running at once; stdout/stderr go to `~/Library/Logs/Nudge/actions.log` (0600, rotated at 1 MB, keeps 1). A non-zero exit posts a notification naming the action.
    - `openURL`: `NSWorkspace.shared.open(url)`.
- **Start button:** runs every `runOnStart` action. The `⌄` menu lists all actions to run one. With no `runOnStart` actions, Start opens the PR in the browser.
- **Shipped default:** one example action, "View diff", terminal kind, template `gh pr diff {number} --repo {repo}`, `runOnStart = false`. It works without a local checkout.

### Examples

GraphQL query (one per sync; `$teamQuery` is not needed because `review-requested:@me` includes team requests):

```graphql
query Waiting($cursor: String) {
  viewer { login }
  search(query: "is:open is:pr archived:false review-requested:@me",
         type: ISSUE, first: 50, after: $cursor) {
    issueCount
    pageInfo { hasNextPage endCursor }
    nodes { ... on PullRequest {
      id number title url isDraft headRefName author { login }
      repository { nameWithOwner }
      reviewRequests(first: 100) { pageInfo { hasNextPage endCursor } nodes { requestedReviewer {
        __typename ... on User { login } ... on Team { slug organization { login } } } } }
      timelineItems(last: 50, itemTypes: [REVIEW_REQUESTED_EVENT, READY_FOR_REVIEW_EVENT]) { nodes {
        __typename
        ... on ReviewRequestedEvent { id createdAt actor { login } requestedReviewer {
          __typename ... on User { login } ... on Team { slug organization { login } } } }
        ... on ReadyForReviewEvent { createdAt } } }
    } }
  }
  rateLimit { cost remaining resetAt }
}
```

Reviewer refetch, used when `reviewRequests.pageInfo.hasNextPage` is true (verified in Phase 0):

```graphql
query Reviewers($id: ID!, $cursor: String) {
  node(id: $id) { ... on PullRequest {
    reviewRequests(first: 100, after: $cursor) { pageInfo { hasNextPage endCursor }
      nodes { requestedReviewer { __typename ... on User { login } ... on Team { slug organization { login } } } } } } }
}
```

## Design Addendum (mockups review, 2026-10-27)

Decisions from the design canvas review that supersede the UI/UX section where they conflict. The mockup sources are the reference for layout and type; this section is the contract.

- **Typography: the timer is the hero.**
  - Collapsed pill: count 17pt heavy, oldest timer 19–21pt heavy, `-0.02em` tracking, tabular digits, SF Pro Rounded.
  - Rows: title 15–16pt bold, subtitle 12–13pt, timer 17–18pt heavy. Tier text colors are darkened for contrast on light glass (amber `#7a3300`, red `#8f1a0e`; dark mode `#ffb35c` / `#ff8a80`).
- **Tier-tinted glass (from concept B).** The pill's glass picks up the oldest request's tier tint: clear (Fresh), amber `rgba(255,170,60,.34)`, red `rgba(255,80,60,.32)`, crossfading over 0.5s. Rows for amber/red requests get a faint matching row tint in the expanded list.
- **Real time vs work time.**
  - The big number is always wall-clock waiting time. Each row carries a small briefcase chip with work time (`2h 48m work`), which drives tier color.
  - Off hours: a moon chip `off hours` slides out of the collapsed pill, and tier dots dim to 45%. The real-time clock keeps running; tier changes and reminders pause.
  - Hovering a row's timer shows a breakdown popover: "Waiting since Fri 4:12 PM", a horizontal timeline with work segments solid and off-hours hatched, and "Turns amber after 1h 12m more work time".
- **Seconds.** Compact `4h 12m` at rest; live `H:MM:SS` while the pill is expanded (hover) or the dropdown is open (click). Notifications never tick.
- **Snooze is a split button.** Left half snoozes for the default (Settings › General, default 1h). The ⌄ menu lists 15m, 1h, 3h, Until tomorrow 9:00, Until next work day, each with its end time, plus a Custom field accepting `45m`, `2h`, `4pm`, `mon`. The last custom value is remembered.
- **Notifications.** Category `REVIEW_REQUEST` actions: `OPEN`, `SNOOZE_1H`, `SNOOZE_TOMORROW`, `SNOOZE_FOR` (a `UNTextInputNotificationAction`, button "Snooze", placeholder "2h, 4pm, mon"), and `START_REVIEW`. macOS folds actions past the first into an Options menu; that's accepted.
- **Settings window.** Frameless tinted glass (dark, `rgba(24,24,30,.62)` with 40pt blur) with an inset floating glass sidebar (General, Notifications, Actions, About), rounded 30pt. Notification rules use per-org cards with a 3-segment Notify/Silent/Hidden control and nested repo overrides. Actions tab: list of action cards on the left, editor on the right with token chips and a live preview of the rendered script (export lines + command).
- **Motion** (each plays once per event; Reduce Motion falls back to crossfade/no-op):
  1. New request: pill bounce, count `.numericText()` roll, new dot `DrawOnSymbolEffect`.
  2. Tier crossing: tint and dot crossfade, one `.wiggle`, work chip rolls to the threshold.
  3. Hover: capsule morphs into the list (`GlassEffectContainer` + `glassEffectID`).
  4. Work day ends: moon chip slides out, dot dims.
  5. Snooze: row slides right into a "Snoozed (n)" group with its return time; count rolls down.
  6. All clear: sparkle + "All clear", then shrink away (Auto) or settle to a ✓ capsule (Widget).
- **PR hover cards.** Hovering a row's title for ~450ms opens a glass card (max 360pt wide, never truncates):
  - **Contents:** full selectable title; `repo #n · by author`; the branch; the request line (`alice requested your review · Tue 2:01 PM`, or `Requested from acme/backend` plus other teams); `Waiting 1d 2h · 9h 12m of work time`; state chips (snoozed, silent, tier); and Open on GitHub / Copy link.
  - **Behavior:** the card stays open while the pointer is over the row or the card, and closes ~200ms after leaving both. Space or ⌥↩ toggles it on a focused dropdown row.
  - **Presentation:** a SwiftUI `.popover`, not `.help()`, because macOS doesn't show tooltips for inactive apps. The pill panel stays expanded while a card is open.
- **Expand/collapse morph.**
  - **Shape:** one glass shape whose size and corner radius spring from capsule to card (`spring(response: 0.38, dampingFraction: 0.82)`). It stays pinned at its snapped corner and grows in both axes. It never swaps views or grows from an edge.
  - **Content:** fades and staggers inside the clip and never reflows.
  - **Panel:** jumps instantly to its expanded frame before the expand starts, and shrinks only after the collapse finishes. No per-frame window resizing.
- **Compact icon rows.** Each row has two lines:
  - **Line 1:** dot, then the title (one line, truncated; the hover card shows the full title), then the heavy timer.
  - **Line 2:** `owner/repo #n · author` on the left. On the right, the work-time chip at rest; on hover it cross-fades to 26pt icon buttons: Start (`play.fill`, blue split button with a menu), Snooze (`moon.zzz`, split button with a menu), Hide (`eye.slash`), Open (`arrow.up.right`).
  - **Labels:** each icon has a custom 11pt mini label after 600ms of hover, plus an accessibility label.
  - **Never:** grouping separators in PR numbers, or debug text.
- **Context menus (right-click).**
  - **Row:** Open on GitHub; Start Review; Run Action ▸; Snooze ▸ (presets + Custom…); Unsnooze; Hide Until Re-requested; Copy Link / Title / `owner/repo#n`; Show Details.
  - **Pill:** Open Menu Bar List; Sync Now; Hide Pill Until Next Request; Show Timers ▸ (Menu Bar Only / Widget / Auto); Settings…; Quit.
  - **Status item:** right-click gives the same pill items plus Show/Hide Pill. Left-click toggles the dropdown.
- **Deferred to follow-up issues:** notch island display mode ([#3](https://github.com/foobarnes/nudge/issues/3)), droplet layout (concept C).

### Tricky / Non-Obvious Parts

- **Timer correctness**
  - `review-requested:@me` also matches team requests. Always re-derive the target from `reviewRequests`, never assume direct.
  - Timeline events are filtered by type *before* `last: 50`, so 50 covers almost every PR. The fallback case still exists; keep the `—` state.
  - Notifications dedupe on `requestKey`, not PR ID. A re-request must notify again; a restart must not.
- **Energy**
  - One shared `TimelineView(.periodic(by: 1))` lives only inside expanded/dropdown views. Collapsed views use a minute-aligned `TimelineView(.everyMinute)`. No per-row timers.
  - Tier and reminder evaluation runs in `AppModel` on a minute-aligned timer, independent of which views are visible. Working-time-so-far is cached per request and extended incrementally, never recomputed day-by-day every second.
- **Agent-app quirks**
  - Settings activation dance (see UI/UX). Request `UNUserNotificationCenter` authorization from `applicationDidFinishLaunching`; no activation is needed (verified in Phase 0 for an ad-hoc-signed `.accessory` app in `/Applications`). The delegate is `@MainActor` with `nonisolated` async delegate methods under Swift 6.
  - Finder-launched apps have no shell PATH; terminal and background actions run through `zsh -lc` so the user's PATH applies.
- **Pill behavior**
  - Hover tracking on a non-activating panel needs an `NSTrackingArea` with `.activeAlways`.
  - Resizing the panel rebuilds the tracking area and can emit spurious enter/exit pairs. Debounce exit (~150ms) and confirm with `NSEvent.mouseLocation` before collapsing (Phase 0).
  - The morph must not resize the window under the cursor mid-hover. Size the panel to the expanded size while expanded, and shrink it back after collapse animates.
- **macOS 27 menu bar**
  - Reports from 27 betas mention `NSStatusItem` highlight regressions. Don't depend on `button.highlight(_:)`; draw the "open" state in the dropdown instead.

### Technology Choices

- **XcodeGen:** keeps the project as a diff-able YAML file; the `.xcodeproj` is generated and git-ignored. Plain Xcode projects produce unreadable diffs. A SwiftPM-only app can't produce a proper app bundle (Info.plist, entitlements) without custom bundling scripts.
- **No third-party Swift packages:** `MenuBarExtraAccess` is unnecessary once the shell is AppKit; Sparkle is deferred with distribution ([#1](https://github.com/foobarnes/nudge/issues/1)).

## Edge Cases and Error Handling

- **GitHub/auth failures** (status glyph gets a `!` badge; the pill shows `stale · synced 12m ago`; timers keep counting, greyed)
  - `gh` not installed → dropdown: "Install GitHub CLI: brew install gh".
  - Not logged in or 401 after re-read → "Run `gh auth login`"; one notification per failure episode.
  - SAML SSO not authorized for an org → GraphQL returns partial data with errors. Show the rows that did return, plus a footer naming the org: "Authorize SSO for acme: gh auth refresh".
  - Rate limited → wait until reset; show "rate limited until 14:05".
  - Offline → backoff; no notification (the stale line is enough).
- **PR state changes**
  - Request removed, PR merged/closed, converted to draft, or review submitted → row leaves with a collapse animation on the next sync. Per-key state is pruned only under the rule in Data Model (absent from complete snapshots for 24h).
  - Reviewer re-requested → new key; un-hides, notifies again, timer restarts.
  - More than 50 waiting PRs → paginate (max 4 pages; beyond that show "200+").
- **Time**
  - Clock skew: `waitingSince` in the future → clamp elapsed to 0.
  - Working hours set to zero days → tiers never escalate; Settings shows a warning.
  - DST transitions and timezone changes (`NSSystemTimeZoneDidChange`) → recompute.
- **Displays and windows**
  - Saved anchor's display missing → default top-right of main display.
  - Full-screen app → pill still shows (`fullScreenAuxiliary`); Auto mode does not force it if mode is Menu bar only.
- **Actions**
  - Ghostty or Terminal not installed → action fails with a notification naming the missing app.
  - Template renders an invalid URL → error alert in Settings preview; run-time failure notification.

## Security Considerations

- **Command injection via PR data**
  - Titles, branches, and repo names are attacker-controlled. PR data never enters shell source: it travels as single-quote-escaped `export` assignments and is referenced as `${NUDGE_PR_*}` (see Action Templates). Tests *execute* rendered scripts with titles containing `'`, `"`, `$(…)`, backticks, `;`, `*`, newlines, and non-ASCII, and assert that a marker file is never created.
  - Actions only run on explicit user clicks, never automatically on arrival.
  - Per-run scripts live in a `0700` directory under `NSTemporaryDirectory()` and are deleted on exit.
- **Token handling**
  - The token is fetched from `gh` per process lifetime, kept in memory, never logged, never persisted. Requests go only to `https://api.github.com/graphql`.
- **Unsandboxed app**
  - Required to spawn `gh`, terminals, and scripts. No incoming network listeners. No dynamic code loading.
- **URL actions**
  - Scheme and host are literal template text; tokens are encoded per component. Allowed schemes: `https` plus user-allowlisted custom schemes; `file`, `javascript`, and `data` are always rejected. Tests cover `&`, `=`, `#`, `%`, `?`, `/`, and a full URL embedded as a value.

## Acceptance Criteria

All `swift test` commands run from `Packages/NudgeKit`. Live GitHub checks that need a second account to request a review are listed in Rollout.

### Request resolution and identity

1. [ ] Resolver handles every case in the Examples table.
       **Required secrets/auth:** None.
       **How to verify:** `swift test --filter ReviewRequestResolverTests` passes, with one test per table row asserting `requestKey`, `waitingSince`, `via`, `otherTeams`, or exclusion exactly as listed.
2. [ ] Notifications fire once per waiting episode across restarts, re-requests, and partial syncs.
       **Required secrets/auth:** None.
       **How to verify:** `swift test --filter NotificationPlannerTests` replays snapshot sequences and asserts the exact banners planned:
       - (a) first launch with a backlog → 0;
       - (b) a new key → 1;
       - (c) the same key after a simulated relaunch (state reloaded from a fresh `UserDefaults` suite) → 0;
       - (d) a re-request (new event ID) → 1;
       - (e) an incomplete snapshot missing a PR, then a complete one containing it → 0 banners and the hidden/snoozed state is kept;
       - (f) direct removed while a team request remains → 0;
       - (g) draft → ready with an unseen key → 1;
       - (h) review submitted and re-requested between two polls (PR present in both snapshots, new event newer than the previous `fetchedAt`) → 1;
       - (i) a hidden request whose key moves unknown → known → still hidden, 0 banners;
       - (j) Silent + snoozed + crosses Red, then snooze expires → 0 reminders;
       - (k) a fresh request present at first launch that later reaches Red → exactly 1 reminder.

### Time and escalation

3. [ ] Working-hours tiers ignore off-hours and handle DST.
       **Required secrets/auth:** None.

       - Fri 2026-01-09 17:00 → Mon 2026-01-12 10:00 = 7,200s.
       - Fri 2026-03-06 17:00 → Mon 2026-03-09 10:00 (DST starts Sun 03-08) = 7,200s.
       - Zero working days → tier stays Fresh after 30 days.
       - Window Sun 01:00–04:00: on 2026-03-08 (spring forward), the full window = 7,200s; on 2026-11-01 (fall back), the full window = 14,400s.
4. [ ] Duration formatting matches spec strings.
       **Required secrets/auth:** None.

6. [ ] Shell actions can't be injected through PR data.

- **Live API check:** a scrubbed real `review-requested:@me` response confirmed the re-request, request-before-ready, and draft-with-active-request cases in the Examples table.
- **Prior art:** Dato, Itsycal, Ice (native restraint); Gitify (Electron footprint as the counter-example).
